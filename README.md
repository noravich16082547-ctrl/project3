# DormCRU — เว็บไซต์หาหอพักสำหรับนักศึกษาปี 1 ราชภัฏเชียงราย
### (เวอร์ชัน GitHub + Vercel + Supabase, ไฟล์แบนราบ)

ดูขั้นตอนติดตั้งทั้งหมดใน **`SETUP-SUPABASE.md`** — สร้าง Supabase, รัน `schema.sql`,
เชื่อม GitHub เข้ากับ Vercel, ตั้งบัญชีแอดมินคนแรก

## โครงสร้างผู้ใช้งาน 3 ระดับ
- **นักศึกษา** — สมัครที่แท็บ "สมัครนักศึกษา" ในหน้า `/login` ค้นหา/จอง/บันทึกหอพักที่ถูกใจ
- **เจ้าของหอพัก** — สมัครที่แท็บ "สมัครเจ้าของหอ" ต้องรอแอดมินอนุมัติก่อนจึงเพิ่ม/แก้ไขหอพักได้
- **แอดมิน** — เห็นและจัดการได้ทุกหอพัก/ทุกการจอง + อนุมัติเจ้าของหอพักรายใหม่

## ทำไมเวอร์ชันนี้ถึงต่างจากเวอร์ชันก่อน
เวอร์ชันก่อนหน้าเก็บไฟล์ไว้ในโฟลเดอร์ `assets/` และให้ JavaScript สร้างเนื้อหาเกือบทั้งหมด
ของหน้าเว็บ — พอ deploy ผิด path หรือ Supabase ยังไม่ได้ตั้งค่า หน้าเว็บเลยพังจนขึ้นว่างเปล่า

เวอร์ชันนี้แก้ 3 อย่าง:
1. **ไฟล์แบนราบทั้งหมด** อยู่ที่รากโปรเจค ไม่มีโฟลเดอร์ย่อย ตัดปัญหา path ผิดตอน deploy
2. **`db.js` ไม่มีวันทำให้หน้าเว็บพัง** — เช็คตัวเองก่อนทุกครั้ง ถ้า Supabase ยังไม่พร้อมจะโชว์
   แบนเนอร์เตือนแทนที่จะปล่อยให้ error หยุดทั้งหน้า
3. **หน้ารายละเอียด/จอง/รายการที่ถูกใจ รวมอยู่ใน `index.html` เป็นโมดัล** แทนการแยกเป็นหลายหน้า
   (ลดความเสี่ยงเรื่องลิงก์ระหว่างหน้าเสีย)

## ไฟล์สำคัญ
- `db.js` — **ต้องแก้ `SUPABASE_URL`/`SUPABASE_ANON_KEY` เป็นค่าจริงก่อนใช้งาน**
- `schema.sql` — รันใน Supabase SQL Editor ครั้งเดียวตอนตั้งค่า
- `index.html` — หน้าแรก ค้นหา/กรอง/รายละเอียด/จอง/wishlist ทั้งหมดในหน้าเดียว อัปเดตห้องว่างแบบเรียลไทม์
- `login.html` — เข้าสู่ระบบ + สมัครนักศึกษา + สมัครเจ้าของหอ (3 แท็บ)
- `admin.html` + `admin.js` — หลังบ้านเจ้าของหอพัก/แอดมิน
- `vercel.json` — clean URL ให้ `/login` และ `/admin` ใช้แทน `.html` ได้

## ข้อควรทราบ
- bucket `slips` ตั้งเป็น public เพื่อความง่าย (ไฟล์เข้าถึงได้ถ้ารู้ลิงก์ตรงๆ ชื่อไฟล์สุ่มไม่ให้เดาง่าย)
- ข้อมูลหอพักตัวอย่างมีคำว่า "(ข้อมูลตัวอย่าง)" กำกับไว้ ให้ลบ/แก้ก่อนเปิดใช้งานจริง
- Supabase free tier จะหยุดทำงานชั่วคราวถ้าไม่มีคนใช้เกิน 7 วัน ต้องกด "Restore project" ปลุกเอง


## อัปเดตล่าสุด: ระบบสำหรับใช้งานจริงกับหอพักจริง

**1. ข้อมูลหอพักจริง (ไม่ใช่หอสมมติ)** — ข้อมูลตั้งต้นเปลี่ยนเป็นหอพักที่มีอยู่จริงรอบ มร.ชร. ต.บ้านดู่
(เวสธิมา คอร์ท หน้ามอ, ฮักล้านนา ประตู 2, หอพักสุนทรี, จงไพศาล 2, บุญมณี ฝั่งประตู 3 ฯลฯ)
รวบรวมจากประกาศสาธารณะ ครอบคลุมทั้ง 3 ประตู **แต่ระบบตั้งสถานะ "รอเจ้าของหอยืนยัน" (verified=false)
ให้ทั้งหมด** เพราะราคา/ห้องว่าง/ช่องทางติดต่อจากประกาศอาจไม่เป็นปัจจุบัน — หอที่ยังไม่ยืนยันจะ:
- แสดงป้ายเตือนชัดเจนว่าข้อมูลรอการยืนยัน
- ไม่แสดงจำนวนห้องว่าง (ขึ้น "สอบถามห้องว่างกับหอโดยตรง" แทน)
- เปิดเฉพาะ "ขอนัดดูห้อง/จองคิวไว้ก่อน" — ไม่เปิดรับโอนมัดจำ เพื่อป้องกันการโอนเงินจากข้อมูลที่ไม่ยืนยัน
วิธียืนยัน: เจ้าของหอตัวจริงสมัครบัญชี → แอดมินอนุมัติ → แอดมินเข้าแก้ไขหอนั้นแล้วติ๊ก "ยืนยันข้อมูลแล้ว"
(หอที่เจ้าของเพิ่มเองใหม่จากหลังบ้าน = verified อัตโนมัติ เพราะเป็นข้อมูลจากเจ้าของโดยตรง)

**2. รูปภาพ** — ใช้ภาพถ่ายจริงจากช่างภาพ (คลังภาพ Pexels) ไม่ใช่ภาพ AI แต่ยังเป็น "ภาพตัวอย่างบรรยากาศ"
ไม่ใช่ภาพถ่ายของอาคารแต่ละหลังจริง เพราะการดึงรูปจริงของธุรกิจมาใช้โดยไม่ได้รับอนุญาตทำไม่ได้
— เจ้าของหอลงรูปจริงของตัวเองแทนได้ทันทีในหลังบ้าน (ช่อง "ลิงก์รูปภาพ")

**3. โหมดจองใหม่: จองไว้ก่อน แล้วนัดทำสัญญา** — นักศึกษากดจอง → กรอกเบอร์โทร + วันเวลาที่สะดวก
→ หอเห็นคำขอในหลังบ้านพร้อมเบอร์ติดต่อกลับ → โทร/ไลน์นัดดูห้อง-ทำสัญญา → กดยืนยันในระบบ
(สลิปมัดจำเปลี่ยนเป็น "ไม่บังคับ" — แนบได้เฉพาะหอที่ยืนยันข้อมูลแล้วและตกลงกันแล้ว)

**4. ช่องทางติดต่อหอพัก** — เพิ่มช่อง เบอร์โทร / LINE / Facebook ต่อหอ แสดงเป็นปุ่มกดโทร-เปิดไลน์-เปิดเพจ
ได้ทันทีในหน้ารายละเอียด เจ้าของหอกรอกเองในหลังบ้าน

**5. เครื่องมือเจ้าของหอ** — ปุ่ม +/− ปรับห้องว่างเร็ว (เปิดห้อง/ปิดห้อง) หน้าตารางจัดการ ไม่ต้องเปิดฟอร์ม,
แก้ราคา, ลงรูป, แก้ช่องทางติดต่อ ได้ครบในฟอร์มแก้ไข

**สำหรับคนที่รัน schema.sql เวอร์ชันเก่าไปแล้ว:** รัน `schema-update.sql` เพิ่มใน SQL Editor
เพื่ออัปเกรดตาราง (คนตั้งโปรเจคใหม่ใช้ `schema.sql` ไฟล์เดียวจบ)


## อัปเดต: ตัดระบบจองออก เปลี่ยนเป็น "ติดต่อหอโดยตรง"

เว็บนี้ทำหน้าที่เป็น **แหล่งรวมข้อมูลหอพัก (directory)** ไม่ใช่ระบบรับจอง/รับเงิน เหตุผล:
ข้อมูลห้องว่างที่แม่นยำอยู่กับหอ การให้นักศึกษาโทร/แชทหาหอโดยตรงเร็วและถูกต้องกว่า
และเว็บไม่ต้องรับความเสี่ยงเรื่องเงินมัดจำ

**ฝั่งนักศึกษา**
- ค้นหา/กรองหอพัก → เปิดดูรายละเอียด → กดปุ่ม **โทร / LINE / Facebook** ติดต่อหอได้ทันที
- หอที่ยังไม่มีช่องทางติดต่อในระบบ จะแนะนำให้ติดต่อสำนักงานบริการที่พักอาศัย มร.ชร. (0-5377-6273)
- บันทึกหอที่ถูกใจ (wishlist) ยังใช้ได้ตามปกติ

**ฝั่งเจ้าของหอ**
- สมัคร → กด "รับช่วงดูแลหอของฉัน" → กรอกราคา ห้องว่าง รูป และ **เบอร์โทร / LINE / Facebook**
- ยิ่งกรอกช่องทางติดต่อครบ นักศึกษายิ่งติดต่อได้ง่าย (การ์ดจะขึ้นป้าย "📞 ติดต่อได้")

**ฝั่งแอดมิน** — ดูภาพรวมระบบและรายชื่อเจ้าของหอเท่านั้น (เมนูตรวจสอบการจองถูกถอดออกแล้ว)

> หมายเหตุ: ตาราง `bookings` ในฐานข้อมูลยังคงอยู่แต่ไม่มีการใช้งานแล้ว
> หากต้องการลบทิ้งให้รันใน SQL Editor: `drop table if exists bookings;`

## อัปเดต v5 — แก้แชท + เพิ่มปุ่มจอง

### 🔴 ต้องทำก่อนใช้งาน: รัน SQL 1 ไฟล์

เปิด **Supabase Dashboard → SQL Editor → New query** วางไฟล์
`fix-chat-booking.sql` ทั้งไฟล์แล้วกด **Run** (รันซ้ำได้ ไม่ลบข้อมูลเดิม)

ไฟล์นี้แก้ error `Could not find the 'sender_role' column of 'messages'`
ซึ่งเกิดจากมีไฟล์ติดตั้งแชท 2 เวอร์ชัน (`chat.sql` กับ `chat-setup.sql`)
ที่สร้างตารางไม่เหมือนกัน และเตรียมคอลัมน์ให้ระบบจองด้วย

### สิ่งที่แก้ในระบบแชท

- เว็บ **ไม่ส่งคอลัมน์ `sender_role`** ไปตอน insert อีกแล้ว → ฐานข้อมูลมี trigger เติมให้เอง
  ทำให้ใช้ได้กับสคีมาทั้งสองแบบ
- `sender_id` ใช้ค่าจาก session จริง (ต้องตรงกับ `auth.uid()` ไม่งั้น RLS ปฏิเสธ)
- การนับ "ยังไม่อ่าน" เปลี่ยนไปเทียบจาก id คนส่งแทนคอลัมน์ `sender_role`
- แท็บ "ข้อความจากนักศึกษา" ในหลังบ้านกดแล้วไม่ขึ้น — เพราะชื่อ section ตกหล่นจาก
  รายการสลับแท็บ (`'messages'` หายไป) แก้แล้ว และลบแท็บที่ซ้ำออก

### ปุ่มจอง (แยกจากปุ่มแชท)

ในหน้ารายละเอียดหอพักจะมี 2 ปุ่มแยกกันชัดเจน:

| ปุ่ม | หน้าที่ |
|------|---------|
| 📌 **จองห้องนี้** | เปิดฟอร์มจอง (เลือกห้อง, เบอร์ติดต่อกลับ, วันที่สะดวกดูห้อง, ข้อความ) → บันทึกลงตาราง `bookings` → เจ้าของหอเห็นในหลังบ้านทันทีแบบเรียลไทม์ + ส่งอีเมลแจ้งเตือน |
| 💬 **แชทกับเจ้าของหอ** | คุยสอบถามทั่วไป ไม่ผูกมัด |

ฝั่งเจ้าของหอมีแท็บใหม่ **📌 คำขอจองห้อง** พร้อมจุดแดงนับคำขอที่ยังไม่ได้อ่าน
กดยืนยันรับจองแล้วระบบจะตัดจำนวนห้องว่างให้อัตโนมัติ

### ตั้งค่าอีเมลแจ้งเตือน (Resend)

ระบบจองใช้งานได้ทันทีแม้ยังไม่ตั้งค่าอีเมล (เจ้าของหอยังเห็นคำขอในหลังบ้าน)
ถ้าอยากให้ส่งอีเมลด้วย ทำตามนี้:

1. สมัคร [resend.com](https://resend.com) (ฟรี 3,000 อีเมล/เดือน) แล้วสร้าง **API Key**
2. ไปที่ Vercel → โปรเจกต์ของคุณ → **Settings → Environment Variables** ใส่ค่า:

   | ชื่อ | ค่า |
   |------|-----|
   | `SUPABASE_URL` | `https://xxxx.supabase.co` (เหมือนใน `db.js`) |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key จาก Supabase → Settings → API |
   | `RESEND_API_KEY` | API key จาก Resend |
   | `MAIL_FROM` | `DormCRU <onboarding@resend.dev>` |
   | `SITE_URL` | `https://ชื่อเว็บของคุณ.vercel.app` |

3. กด **Redeploy** หนึ่งครั้ง

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` ใช้ได้เฉพาะฝั่งเซิร์ฟเวอร์ (โฟลเดอร์ `api/`) เท่านั้น
> **ห้ามเอาไปใส่ใน `db.js` หรือไฟล์หน้าเว็บเด็ดขาด** เพราะ key นี้ข้าม RLS ได้ทั้งหมด

โดเมนผู้ส่ง: ตอนทดสอบใช้ `onboarding@resend.dev` ได้เลย แต่ถ้าจะใช้จริงจัง
ควรยืนยันโดเมนของตัวเองใน Resend ก่อน อีเมลจะได้ไม่ตกโฟลเดอร์สแปม

*คำขอ* ที่รอผู้ดูแลระบบตรวจสอบ (ตาราง `dorm_claims`) — แอดมินดูคำขอได้ที่แท็บ
**🛡️ ตรวจสอบคำขอดูแลหอ** พร้อมข้อมูลยืนยันตัวตนที่ผู้ขอกรอกมา
ฟังก์ชันเดิม `claim_dorm()` ถูกเปลี่ยนให้กลายเป็นการยื่นคำขอด้วย เผื่อมีโค้ดเก่าค้างอยู่

**2. ปิดช่องโหว่ "ตั้งตัวเองเป็นแอดมิน"**
เพิ่ม trigger + RLS บังคับว่าสมัครเองได้แค่ `student`/`owner` และ `approved`
เป็น false เสมอ — เปลี่ยนเป็นแอดมินได้จาก SQL Editor ทางเดียว
บัญชีเจ้าของหอเดิมที่เคยถูกตั้ง approved=true อัตโนมัติและยังไม่ได้ดูแลหอไหน
จะถูกปรับกลับเป็นรอตรวจสอบ

**3. ติดป้ายรูปภาพประกอบ**
หอที่ยังใช้รูปสต็อกจะขึ้นป้ายแดง **🖼 ภาพประกอบ** บนการ์ด และมีแถบเตือน
"รูปด้านล่างเป็นภาพประกอบ ไม่ใช่ห้องจริงของหอนี้" ในหน้ารายละเอียด
พอเจ้าของหอใส่ลิงก์รูปจริง (ช่อง "ลิงก์รูปภาพ" ในหลังบ้าน) ป้ายจะหายไปเอง

**4. เมนู "📌 การจองของฉัน" ฝั่งนักศึกษา**
ดูสถานะคำขอจองทุกรายการ (รอหอตอบกลับ / หอรับจองแล้ว / ยกเลิกแล้ว)
พร้อมปุ่มคุยกับหอ และยกเลิกคำขอที่ยังรออยู่ได้เอง

**5. คืนห้องว่างเมื่อยกเลิกการจองที่ยืนยันแล้ว**
`confirm_booking()` เดิมหักห้องว่างตอนยืนยันแต่ไม่คืนตอนยกเลิก ทำให้ตัวเลขเพี้ยนสะสม
ตอนนี้ดูสถานะเดิมก่อนเสมอ — ยืนยันซ้ำไม่หักซ้ำ ยกเลิกแล้วคืนห้อง และไม่มีทางเกินจำนวนห้องทั้งหมด

### ขั้นตอนใหม่สำหรับเจ้าของหอ

1. สมัครบัญชีเจ้าของหอ → เข้าหลังบ้านได้เฉพาะหน้า "รับช่วงดูแลหอของฉัน"
2. กด "นี่คือหอของฉัน" ที่หอของตัวเอง แล้วกรอกข้อมูลยืนยันตัวตน
3. ผู้ดูแลระบบโทรตรวจสอบกับหอตัวจริง แล้วกดอนุมัติ
4. เจ้าของหอถึงจะแก้ข้อมูลหอ รับข้อความ และรับการจองได้

## อัปเดต v7 — อีเมลแจ้งเตือนส่งไปที่อีเมลที่เจ้าของหอกรอกเอง

รัน **`add-contact-email.sql`** ใน Supabase SQL Editor (รันซ้ำได้)

### เจ้าของหอกำหนดอีเมลรับแจ้งเตือนเองได้

หลังบ้าน → จัดการห้องพัก → แก้ไข → ช่อง **📧 อีเมลรับแจ้งเตือนการจอง**
มีปุ่ม **✉️ ส่งอีเมลทดสอบ** ให้กดเช็กได้ทันทีว่าเมลถึงจริงไหม (และตกสแปมหรือเปล่า)

ลำดับการเลือกอีเมลปลายทาง:

1. อีเมลที่กรอกไว้ในข้อมูลหอ (`dorms.contact_email`)
2. ถ้าเว้นว่าง → อีเมลที่เจ้าของหอใช้สมัครสมาชิก

### ⚠️ แก้คำแนะนำเดิมเรื่อง Resend

รอบก่อน README บอกให้ใช้ `onboarding@resend.dev` ได้เลย — **อันนั้นใช้จริงไม่ได้**
Resend อนุญาตให้โดเมนทดสอบนี้ส่งได้เฉพาะอีเมลของเจ้าของบัญชี Resend เท่านั้น
ส่งหาเจ้าของหอคนอื่นจะโดน 403 ตอนนี้ระบบรองรับ 2 ทางเลือก:

| | Brevo (แนะนำถ้าไม่มีโดเมน) | Resend |
|---|---|---|
| ต้องมีโดเมนของตัวเอง | ไม่ต้อง — ยืนยันแค่อีเมลผู้ส่ง (Gmail ก็ได้) | ต้องมีและยืนยัน DNS |
| โควตาฟรี | 300 อีเมล/วัน | 3,000/เดือน และ 100/วัน |
| ตัวแปรที่ตั้ง | `BREVO_API_KEY` | `RESEND_API_KEY` |
| `MAIL_FROM` | `DormCRU <อีเมลที่ยืนยันกับ Brevo>` | `DormCRU <noreply@โดเมนคุณ>` |

ตั้งเจ้าไหนก็ได้เจ้าเดียว ถ้าตั้งทั้งคู่ระบบจะใช้ Brevo ก่อน
เมื่อส่งไม่สำเร็จ ระบบจะบันทึกสาเหตุไว้ในคอลัมน์ `bookings.notify_error`
และหน้าคำขอจองจะยังขึ้นว่า "ยังไม่ได้ส่งอีเมล" ให้เห็น

### วิธีตั้งค่า Brevo (ใช้ Gmail เป็นผู้ส่ง)

1. สมัคร brevo.com → **Senders & IP → Senders → Add a sender** ใส่ Gmail ของคุณ
   แล้วกดยืนยันจากลิงก์ในเมลที่ Brevo ส่งไปให้
2. **SMTP & API → API Keys → Generate a new API key**
3. ใส่ใน Vercel → Settings → Environment Variables:
   `BREVO_API_KEY` และ `MAIL_FROM` = `DormCRU <อีเมลที่เพิ่งยืนยัน>`
4. Redeploy แล้วกดปุ่ม "ส่งอีเมลทดสอบ" ในหลังบ้าน

### หมายเหตุ: ลำดับการอัปเดต

ทุกครั้งที่มีไฟล์ `.sql` ใหม่ ให้ **รัน SQL ใน Supabase ก่อน** แล้วค่อยอัปโหลดไฟล์เว็บ
ถ้าอัปโหลดไฟล์เว็บก่อน จะเจอ error แบบ
`Could not find the 'xxx' column of 'yyy' in the schema cache`

ตั้งแต่เวอร์ชันนี้ ถ้าเจอกรณีนั้นกับช่อง "อีเมลรับแจ้งเตือน" ระบบจะไม่พังทั้งหน้า —
จะบันทึกข้อมูลส่วนที่เหลือให้ก่อน แล้วขึ้นข้อความบอกว่าต้องไปรันไฟล์ SQL ไหน

ถ้ารัน SQL แล้วยังขึ้น error เดิม ให้สั่งรีโหลด schema cache ของ Supabase:
```sql
notify pgrst, 'reload schema';
```

## ไล่หาสาเหตุเมื่อ "ส่งอีเมลทดสอบ" ไม่สำเร็จ

### ขั้นที่ 1 — เช็กว่าโฟลเดอร์ `api/` ถูก deploy หรือยัง

เปิดเบราว์เซอร์ไปที่ **`https://ชื่อเว็บของคุณ.vercel.app/api/health`**

| สิ่งที่เห็น | แปลว่า | ต้องทำ |
|---|---|---|
| ข้อความ JSON ขึ้นมา | โฟลเดอร์ `api/` ใช้งานได้แล้ว | ไปขั้นที่ 2 |
| หน้า **404 Not Found** | Vercel หาโฟลเดอร์ `api/` ไม่เจอ | ดูขั้นที่ 1.1 |

### ขั้นที่ 1.1 — แก้กรณี 404

สาเหตุที่พบบ่อยที่สุดคือ **โฟลเดอร์ `api/` ไม่ได้อยู่ระดับบนสุดของโปรเจกต์**
Vercel จะสร้าง Serverless Function ให้เฉพาะไฟล์ที่อยู่ใน `api/` ที่ราก (root) เท่านั้น

โครงสร้างที่ถูกต้อง — `api` ต้องอยู่ระดับเดียวกับ `index.html`:

```
โปรเจกต์ (root)
├── index.html
├── admin.html
├── db.js
├── style.css
└── api/
    ├── notify-booking.js
    └── health.js
```

ถ้าโครงสร้างเป็นแบบนี้จะไม่ทำงาน (ลึกไปหนึ่งชั้น):

```
โปรเจกต์ (root)
└── dormcru-vercel/      <-- ผิด
    ├── index.html
    └── api/
```

**วิธีแก้ตามรูปแบบการ deploy:**

- **ลากไฟล์ใส่ Vercel โดยตรง** — ต้องลาก *ไฟล์ทั้งหมดข้างใน* โฟลเดอร์ `dormcru-vercel`
  ไม่ใช่ลากตัวโฟลเดอร์
- **ผ่าน GitHub** — ย้ายไฟล์ทั้งหมดขึ้นมาไว้ที่รากของ repo
  หรือไปที่ Vercel → Settings → **Root Directory** แล้วตั้งเป็น `dormcru-vercel`
- หลังแก้แล้วต้องกด **Redeploy** หนึ่งครั้งเสมอ

ตรวจซ้ำได้ที่ Vercel → โปรเจกต์ → **Deployments** → คลิก deployment ล่าสุด → แท็บ **Functions**
ต้องเห็นรายชื่อ `api/notify-booking` และ `api/health` อยู่

### ขั้นที่ 2 — เช็ก Environment Variables

หน้า `/api/health` จะบอกว่าตัวแปรไหน "ตั้งค่าแล้ว" หรือ "ยังไม่ได้ตั้งค่า"
(ไม่แสดงค่าจริงของ API key เพื่อความปลอดภัย) ดูบรรทัด **พร้อมส่งอีเมลหรือยัง**
ถ้าขึ้นว่า "ยังไม่พร้อม" ให้ไปเติมตัวแปรที่ขาดใน Vercel → Settings → Environment Variables
แล้ว **Redeploy** (ตัวแปรใหม่จะมีผลเฉพาะ deployment ใหม่เท่านั้น)

### ขั้นที่ 3 — ถ้ายังไม่ได้

กดปุ่ม "ส่งอีเมลทดสอบ" อีกครั้ง แล้วเปิด Console ของเบราว์เซอร์ (F12)
ระบบจะพิมพ์รหัสสถานะและคำตอบจริงจากเซิร์ฟเวอร์ออกมาให้ดู
หรือดูที่ Vercel → โปรเจกต์ → **Logs** จะเห็น error ฝั่งเซิร์ฟเวอร์ทั้งหมด

# ตั้งค่าแจ้งเตือนเข้า LINE (ทีละขั้น)

ระบบนี้ทำงาน **ควบคู่กับอีเมล ไม่ได้แทนที่กัน** — เจ้าของหอที่เชื่อม LINE ไว้จะได้ทั้งสองทาง
ใครยังไม่เชื่อมก็ยังได้รับอีเมลเหมือนเดิม

> **หมายเหตุ:** LINE Notify ที่เคยง่ายมาก ๆ ปิดบริการไปแล้วตั้งแต่ 31 มีนาคม 2025
> ต้องใช้ LINE Messaging API แทน ซึ่งเป็นวิธีที่คู่มือนี้ใช้

## ขั้นที่ 0 — รัน SQL

Supabase → SQL Editor → New query → วางไฟล์ **`add-line-notify.sql`** ทั้งไฟล์ → Run

---

## ขั้นที่ 1 — สร้าง LINE Official Account

1. เข้า **https://manager.line.biz** แล้วล็อกอินด้วยบัญชี LINE ส่วนตัว
2. กด **สร้างบัญชีใหม่ / Create new account**
3. กรอกข้อมูล:
   - ชื่อบัญชี: `DormCRU เชียงราย`
   - ประเภทธุรกิจ: การศึกษา (หรือใกล้เคียง)
   - ประเทศ: ไทย
4. สร้างเสร็จแล้วจดค่านี้ไว้: **Basic ID** หน้าตาเหมือน `@123abcd`
   (ดูได้ที่ Settings → Account settings → Basic ID)

---

## ขั้นที่ 2 — เปิด Messaging API

ยังอยู่ใน LINE Official Account Manager:

1. **Settings → Messaging API**
2. กด **Enable Messaging API / ใช้ Messaging API**
3. เลือก Provider (ถ้ายังไม่มีให้กดสร้างใหม่ ตั้งชื่ออะไรก็ได้ เช่น `DormCRU`)
4. กดยืนยันจนเสร็จ

จากนั้นไปที่ **https://developers.line.biz/console** → เลือก Provider → เลือก Channel ที่เพิ่งสร้าง

**แท็บ Messaging API** — จดค่า 2 ตัวนี้:

| ค่าที่ต้องจด | หาได้ที่ |
|---|---|
| **Channel access token (long-lived)** | แท็บ Messaging API → เลื่อนลงล่างสุด → กด **Issue** |
| **Channel secret** | แท็บ **Basic settings** → หัวข้อ Channel secret |

⚠️ สองค่านี้เป็นความลับ ห้ามใส่ในไฟล์หน้าเว็บ ใส่ได้เฉพาะ Environment Variables ของ Vercel

---

## ขั้นที่ 3 — ปิดระบบตอบกลับอัตโนมัติของ LINE

ถ้าไม่ปิด บอทจะตอบข้อความอัตโนมัติทับของเรา

ใน LINE Official Account Manager → **Settings → Response settings**:

| หัวข้อ | ตั้งเป็น |
|---|---|
| Chat / แชท | เปิด |
| Greeting message / ข้อความทักทาย | **ปิด** |
| Auto-response / ตอบกลับอัตโนมัติ | **ปิด** |
| Webhook | **เปิด** |

---

## ขั้นที่ 4 — ใส่ Environment Variables ใน Vercel

Vercel → โปรเจกต์ของคุณ → **Settings → Environment Variables** เพิ่ม 2 ตัว:

| ชื่อ | ค่า |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | Channel access token จากขั้นที่ 2 |
| `LINE_CHANNEL_SECRET` | Channel secret จากขั้นที่ 2 |

(ต้องมี `SUPABASE_URL` กับ `SUPABASE_SERVICE_ROLE_KEY` อยู่แล้วจากรอบก่อน)

กด **Redeploy** หนึ่งครั้ง — ตัวแปรใหม่มีผลเฉพาะ deployment ใหม่เท่านั้น

---

## ขั้นที่ 5 — ตั้ง Webhook URL

กลับไปที่ **https://developers.line.biz/console** → Channel ของคุณ → แท็บ **Messaging API**

1. ช่อง **Webhook URL** ใส่:
   ```
   https://ชื่อเว็บของคุณ.vercel.app/api/line-webhook
   ```
2. กด **Update** แล้วกด **Verify**
   - ขึ้น **Success** = ใช้ได้
   - ขึ้น Error = ดูตารางแก้ปัญหาท้ายหน้านี้
3. เปิดสวิตช์ **Use webhook** ให้เป็นสีเขียว

---

## ขั้นที่ 6 — ใส่ Basic ID ลงในเว็บ

เปิดไฟล์ **`db.js`** หาบรรทัด `const LINE_OA = {` แล้วกรอก Basic ID จากขั้นที่ 1:

```js
const LINE_OA = {
  basicId: '@123abcd',     // <-- ใส่ของคุณตรงนี้
  addFriendUrl: ''         // เว้นว่างไว้ ระบบจะสร้างลิงก์ให้เอง
};
```

อัปโหลดไฟล์ขึ้น Vercel แล้ว Redeploy

---

## ขั้นที่ 7 — ทดสอบ

1. เข้าหลังบ้าน DormCRU → เมนู **🔔 แจ้งเตือนเข้า LINE**
2. สแกน QR แอด OA เป็นเพื่อน → บอทจะทักกลับมาอธิบายวิธีใช้
3. กด **ขอรหัส 6 หลัก** → พิมพ์รหัสส่งในแชท LINE
4. บอทตอบ **"เชื่อมต่อสำเร็จ ✅"**
5. กลับมาที่หน้าเดิม กด **ตรวจสอบสถานะการเชื่อมต่อ** → ขึ้น "เชื่อมต่อแล้ว"
6. กด **🔔 ทดสอบส่งเข้า LINE** → ต้องมีข้อความเด้งเข้า LINE

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| กด Verify แล้วขึ้น **404** | Vercel หาโฟลเดอร์ `api/` ไม่เจอ | ดูหัวข้อ "ไล่หาสาเหตุเมื่อส่งอีเมลทดสอบไม่สำเร็จ" ด้านบน — เช็กที่ `/api/health` ก่อน |
| กด Verify แล้วขึ้น **401** | `LINE_CHANNEL_SECRET` ผิดหรือยังไม่ Redeploy | ตรวจว่าคัดลอกครบ ไม่มีเว้นวรรคหน้า-หลัง แล้ว Redeploy |
| บอทไม่ตอบอะไรเลย | ยังไม่ได้เปิด **Use webhook** หรือยังเปิด Auto-response อยู่ | ทำขั้นที่ 3 และ 5 ให้ครบ |
| บอทตอบว่ารหัสหมดอายุ | รหัสมีอายุ 15 นาที | กดขอรหัสใหม่ |
| เชื่อมแล้วแต่ไม่มีข้อความเข้า | โควตาหมด (ฟรี 300 ข้อความ/เดือน) | ดูคอลัมน์ `line_error` ในตาราง `bookings` จะบอกสาเหตุไว้ |

## ข้อควรรู้เรื่องโควตา

- แพ็กเกจฟรีของ LINE OA ไทย = **300 ข้อความ push ต่อเดือน** ครบแล้วหยุดส่ง (ไม่คิดเงินเพิ่ม)
- แจ้งเตือนการจอง 1 ครั้ง = 1 ข้อความ
- ข้อความที่บอทตอบกลับในแชท (เช่น ตอบว่าเชื่อมต่อสำเร็จ) **ไม่นับ** เพราะเป็น reply ไม่ใช่ push
- ถ้าโควตาหมด ระบบจะบันทึกไว้ในคอลัมน์ `line_error` และ**ยังส่งอีเมลให้ตามปกติ**

### เปลี่ยนรูป QR แอดเพื่อน LINE

ไฟล์ `line-qr.png` คือ QR ทางการที่ดาวน์โหลดจาก LINE OA Manager
(ปุ่ม "ดาวน์โหลด" ในหน้า หน้าหลัก → เพิ่มเพื่อน → QR code)

ถ้าเปลี่ยน LINE OA ในอนาคต ให้ทำ 2 อย่าง:

1. ดาวน์โหลด QR ชุดใหม่จาก LINE OA แล้วเอาไฟล์ขนาด M (360×360) มาแทนที่ `line-qr.png`
2. แก้ค่าใน `db.js`:

```js
const LINE_OA = {
  basicId: '@ไอดีใหม่',
  addFriendUrl: 'https://lin.ee/xxxxx',   // ลิงก์เพิ่มเพื่อนจาก LINE OA
  qrImage: 'line-qr.png'                  // เว้นว่าง = ให้ระบบสร้าง QR เองจากลิงก์
};
```

ถ้า `qrImage` เว้นว่างไว้ ระบบจะสร้าง QR ขึ้นมาเองจาก `addFriendUrl` (เป็น QR ขาวดำธรรมดา
ไม่มีโลโก้ LINE) — ใช้ได้เหมือนกันแต่ QR ทางการสแกนติดง่ายกว่า

## อัปเดต v12 — เจ้าของหอเพิ่มหอเองได้ + ตั้งแอดมินจากหน้าเว็บ

รัน **`fix-owner-selfservice.sql`** ใน Supabase SQL Editor

### แก้ทางตัน 2 อย่างจากระบบอนุมัติรอบก่อน

**1. เจ้าของหอที่หอยังไม่อยู่ในลิสต์ 61 หอ ทำอะไรไม่ได้เลย**

เดิมเจ้าของหอใหม่ทำได้แค่ "รับช่วงดูแลหอ" ที่มีอยู่แล้ว ถ้าหอตัวเองยังไม่อยู่ในระบบก็จบ
ตอนนี้กด **"+ เพิ่มหอพักใหม่"** ได้ตั้งแต่ยังไม่ผ่านการตรวจสอบ

- หอที่เพิ่มเองจะมีสถานะ **รอตรวจสอบ** — ยังไม่แสดงให้นักศึกษาเห็น
- เจ้าของหอแก้ข้อมูลหอตัวเองได้เรื่อย ๆ ระหว่างรอ
- ฐานข้อมูลบังคับว่าเจ้าของหอ **ตั้งสถานะเผยแพร่ให้ตัวเองไม่ได้** ต้องให้แอดมินกดเท่านั้น
- แอดมินอนุมัติที่เมนู 🛡️ **ตรวจสอบคำขอดูแลหอ** → หัวข้อ "หอพักใหม่ที่เจ้าของหอส่งเข้ามา"
- กดอนุมัติ = เผยแพร่หอ + ปลดล็อกบัญชีเจ้าของหอ ในคลิกเดียว

**2. ไม่มีแอดมิน = ไม่มีใครกดอนุมัติได้ (วงจรตัน)**

เพิ่มปุ่ม **"ตั้งบัญชีนี้เป็นผู้ดูแลระบบคนแรก"** ในหน้าหลังบ้าน ไม่ต้องเขียน SQL

เงื่อนไขความปลอดภัย 2 ชั้น ต้องผ่านทั้งคู่:

1. ระบบต้องยังไม่มีผู้ดูแลระบบเลยสักคน
2. ผู้กดต้องเป็น **บัญชีแรกสุดที่สมัครในระบบนี้** เท่านั้น

พอมีแอดมินคนแรกแล้ว ปุ่มจะหายไปถาวร หลังจากนั้นเพิ่มแอดมินคนอื่นได้ด้วยฟังก์ชัน
`grant_admin('อีเมล')` หรือ SQL ตามเดิม

### หมายเหตุทางเทคนิค

trigger `prevent_self_promote` ถูกเขียนใหม่เป็น **security invoker** (ของเดิมเป็น definer)
เพราะฟังก์ชันแบบ definer จะทำให้ `current_user` กลายเป็นเจ้าของฟังก์ชันเสมอ
เงื่อนไขแยกแยะ "ผู้ใช้ยิงคำสั่งเอง" กับ "ระบบสั่งผ่านฟังก์ชันที่เชื่อถือได้" จึงใช้ไม่ได้
ผลคือกันการยกระดับสิทธิ์ไม่ได้จริง — แก้แล้วและทดสอบยืนยันแล้ว

## 1. หน้าหลังบ้านของเจ้าของหอ = หน้าโปรไฟล์หอพัก

เมนูแรกเปลี่ยนจาก "ภาพรวมระบบ" เป็น **"🏡 หน้าหอพักของฉัน"**
หน้าตาเหมือนหน้าที่พักในเว็บจองโรงแรม แต่แก้ไขได้จากหน้านี้เลย

- **รูปปกใหญ่** + แกลเลอรีรูปทั้งหมด — กด ⭐ ตั้งเป็นรูปปก, กด ✕ ลบรูป
- **ปุ่ม "📷 เพิ่มรูปจากเครื่อง"** อยู่บนรูปปกเลย
- **ช่องคำอธิบายหอ** พิมพ์แล้วกดบันทึกได้ทันที ไม่ต้องเปิดฟอร์มยาว
- **ห้องพักและราคา** ปรับจำนวนห้องว่างด้วยปุ่ม − / + ได้จากหน้านี้
- **ช่องทางติดต่อ** ที่นักศึกษาเห็น
- **กล่องรีวิว** คะแนนเฉลี่ยและรีวิวทั้งหมดของหอคุณ
- ปุ่ม **"👁 ดูหน้าที่นักศึกษาเห็น"** เปิดหน้าจริงในแท็บใหม่
- เจ้าของหอที่มีหลายหอ จะมีแถบสลับหออยู่ด้านบน
- เจ้าของหอที่ยังไม่มีหอเลย จะเห็นปุ่ม **"+ สร้างหน้าหอพักของฉัน"**

ผู้ดูแลระบบยังเห็นตัวเลขภาพรวมระบบเหมือนเดิม (แต่ **เอา QR โค้ดออกแล้ว** ตามที่ขอ —

## 2. อัปโหลดรูปจากเครื่อง ครั้งละหลายรูป ไม่ต้องใส่ comma

ช่อง "ลิงก์รูปภาพ (คั่นด้วย comma)" **ถูกเอาออกแล้ว** เปลี่ยนเป็น

- ปุ่ม **เลือกรูปจากเครื่อง** — เลือกทีละหลายรูปได้ (กด Ctrl ค้างตอนเลือก)
- **ลากไฟล์มาวาง** ในกรอบก็ได้
- รูปที่เลือกจะขึ้นเป็นภาพย่อทันที กด ✕ เอาออก หรือ ⭐ ตั้งเป็นรูปปก
- ระบบ**ย่อขนาดรูปให้อัตโนมัติ** (ด้านยาวสุดไม่เกิน 1600 px) รูปจากมือถือ 5 MB
  จะเหลือไม่กี่ร้อย KB — อัปโหลดเร็วและไม่กินโควตาฟรีของ Supabase
- ถ้ามีลิงก์รูปจากเว็บอื่นอยู่แล้ว ยังวางได้ที่ "มีลิงก์รูปจากเว็บอื่นอยู่แล้ว?" ด้านล่าง

ไฟล์จะถูกเก็บที่ `dorm-photos/<รหัสผู้ใช้ของคุณ>/...`
ฐานข้อมูลบังคับไว้ว่าอัปโหลดได้เฉพาะในโฟลเดอร์ของตัวเอง คนอื่นเอารูปมาใส่หอคุณไม่ได้

## 4. กล่องรีวิวจากผู้ใช้

ในหน้ารายละเอียดหอ (ฝั่งนักศึกษา) ล่างสุดมีกล่องรีวิว

- คะแนนเฉลี่ย + แท่งกระจายคะแนน 1–5 ดาว
- ให้ดาวโดยแตะดาว แล้วเขียนข้อความ
- **1 คน รีวิวได้ 1 ครั้งต่อ 1 หอ** — เข้ามาใหม่จะกลายเป็น "แก้ไขรีวิวของคุณ" และลบรีวิวตัวเองได้
- คนที่ยังไม่ล็อกอิน **อ่านรีวิวได้** แต่เขียนไม่ได้
- **เจ้าของหอรีวิวหอของตัวเองไม่ได้** (ฐานข้อมูลปฏิเสธ ไม่ใช่แค่ซ่อนปุ่ม)
- ชื่อผู้เขียนถูกเติมโดยฐานข้อมูลจากโปรไฟล์ **สวมชื่อคนอื่นไม่ได้**
- คะแนนดาวจะขึ้นบนการ์ดหอในหน้าค้นหาด้วย

# อัปเดต v16 — เอาหอพักตั้งต้น 61 หอออก

## ทำไมถึงเอาออก

รายชื่อหอพักเครือข่าย 61 หอที่ระบบใส่ไว้ให้ตั้งแต่แรก **ไม่มีราคา ไม่มีห้องว่าง
ไม่มีเบอร์ติดต่อ และรูปที่ขึ้นเป็นรูปสต็อกจากเว็บฟรี ไม่ใช่ห้องจริงของหอ**
นักศึกษากดเข้าไปดูแล้วไม่ได้ข้อมูลอะไรเลย และรูปที่ไม่ตรงกับห้องจริงอาจทำให้เข้าใจผิดได้

ตอนนี้ DormCRU แสดงเฉพาะหอที่ **เจ้าของหอสมัครแล้วสร้างหน้าหอของตัวเอง**
ทุกหอที่นักศึกษาเห็นจึงมีคนดูแลจริง ตอบแชทได้จริง และรูปเป็นห้องจริง

## วิธีลบออกจากฐานข้อมูล

เปิด **Supabase → SQL Editor → New query** วางไฟล์ **`remove-seed-dorms.sql`** แล้วกด **Run**

ไฟล์นี้จะ

1. บอกก่อนว่าจะลบกี่หอ และเหลือกี่หอ
2. ลบการจอง / ข้อความ / รีวิว ที่ผูกกับหอตั้งต้นเหล่านั้น
3. ลบตัวหอพักออก
4. แสดงรายชื่อหอที่เหลือให้ดู

**ปลอดภัยกับข้อมูลจริง** — ลบเฉพาะแถวที่คำอธิบายตรงกับข้อความตั้งต้นของระบบเป๊ะ ๆ
หอที่เจ้าของหอตัวจริงสร้างเอง หรือหอตั้งต้นที่มีเจ้าของเข้ามาแก้คำอธิบายแล้ว จะไม่ถูกแตะ
(ทดสอบกับฐานข้อมูล PostgreSQL จริงแล้ว: ใส่หอตั้งต้น 61 หอ + หอเจ้าของจริง 2 หอ
รันไฟล์นี้แล้วเหลือ 2 หอของเจ้าของจริง พร้อมรีวิวของหอนั้นครบ)

## สิ่งที่เปลี่ยนในโค้ดด้วย

- ตัด `SEED_DORMS_RAW` (รายชื่อ 61 หอ) และรูปสต็อก Pexels ออกจาก `db.js` แล้ว
- ลบปุ่ม **"โหลดข้อมูลหอพักตัวอย่าง"** ในหลังบ้านออก — ไม่งั้นพอลบหมดแล้ว
  ปุ่มนี้จะโผล่ขึ้นมาอีก แล้วเผลอกดทีเดียวหอ 61 หอกลับมาทั้งหมด
- หน้าค้นหาฝั่งนักศึกษา ตอนที่ยังไม่มีหอเลย จะไม่ขึ้นหน้าว่างเปล่า
  แต่ขึ้นข้อความอธิบาย + ปุ่ม **"ลงหอพักของคุณ (สำหรับเจ้าของหอ)"**
- แก้ข้อความหน้าแรกและท้ายเว็บให้ตรงความจริง (ข้อมูลมาจากเจ้าของหอ ไม่ใช่การรวบรวม)

## อยากได้กลับมาทำยังไง

รันไฟล์ **`insert-dorms.sql`** ใน Supabase อีกครั้ง ข้อมูลชุดเดิมจะกลับมาครบ 61 หอ

## เจ้าของหอ: วาดผังหอของตัวเอง

เข้าหลังบ้าน → **หน้าหอพักของฉัน** เลื่อนลงมาที่การ์ด **"ผังห้องพัก"**

| ปุ่ม | ใช้ทำอะไร |
|---|---|
| **+ เพิ่มชั้น** | หอมี 3 ชั้นก็เพิ่ม 3 ชั้น ตั้งชื่อชั้นเองได้ |
| **+ เพิ่มแถว** | หนึ่งชั้นมีได้หลายแถว (เช่น ห้องฝั่งซ้าย/ฝั่งขวาของทางเดิน) |
| **✚** ท้ายแถว | เพิ่มห้อง — ระบบตั้งเลขห้องต่อให้เอง (ชั้น 1 → 101, 102... ชั้น 2 → 201...) |
| **🪜** ท้ายแถว | แทรกบันได ลิฟต์ หรือช่องว่าง ไว้ตรงไหนของแถวก็ได้ |
| **กดที่ช่องห้อง** | เปิด pop up แก้เลขห้อง ประเภทห้อง ราคาเฉพาะห้อง สถานะ และหมายเหตุ |

## สีของห้อง

| สี | สถานะ | เกิดขึ้นเมื่อไหร่ |
|---|---|---|
| 🩶 **เทา** | ว่าง | ห้องพร้อมให้เช่า นักศึกษากดจองได้ |
| 🟥 **แดง** | มีคนจองแล้ว | นักศึกษากดจองห้องนี้ **รอคุณกดยืนยันรับจอง** |
| 🟦 **น้ำเงิน** | มีผู้เช่าอยู่ | คุณกด "ยืนยันรับจอง" แล้ว หรือตั้งเองสำหรับห้องที่มีคนอยู่ก่อน |
| ⬛ **เทาเข้ม** | ปิดปรับปรุง | ไม่ปล่อยเช่าตอนนี้ เช่น กำลังซ่อม |

**สีเปลี่ยนเองอัตโนมัติ** ตามการจอง — ไม่ต้องมาไล่กดเอง

```
นักศึกษากดจองห้อง 101   ->  ห้อง 101 เป็นสีแดงทันที
คุณกด "ยืนยันรับจอง"     ->  ห้อง 101 เป็นสีน้ำเงิน
คุณกด "ปฏิเสธ"          ->  ห้อง 101 กลับเป็นสีเทา
นักศึกษากดยกเลิกเอง      ->  ห้อง 101 กลับเป็นสีเทา
```

และ **คุณปรับสถานะเองได้ตลอด** จาก pop up ของห้องนั้น
(ถ้าห้องมีคนจองค้างอยู่ ระบบจะถามยืนยันก่อน กันกดพลาด)

---

## นักศึกษา: กดจองห้องที่ต้องการได้เลย

ในหน้ารายละเอียดหอ จะมีหัวข้อ **"ผังห้องพัก"** บอกว่าหอมีกี่ชั้น ห้องไหนว่าง

- กดที่ **ห้องสีเทา** = จองห้องนั้นโดยตรง ฟอร์มจะขึ้นบอกชัดว่ากำลังจองห้องไหน ชั้นไหน ราคาเท่าไหร่
- ห้องแดง/น้ำเงิน/เทาเข้ม **กดไม่ได้** — จองได้เฉพาะห้องที่ว่างจริง
- ห้องที่ตัวเองจองไว้จะมีกรอบสีทองและเขียนว่า **"คุณจองไว้"**
- ใบจองที่ส่งไปหาเจ้าของหอจะระบุ **เลขห้องและชั้น** ให้เลย ไม่ต้องมาถามกันซ้ำ

**กันจองซ้ำ** — ถ้ามีคนกดจองห้องเดียวกันตัดหน้าไปเสี้ยววินาที ฐานข้อมูลจะปฏิเสธ
แล้วขึ้นข้อความว่า "ห้องนี้ไม่ว่างแล้ว กรุณาเลือกห้องอื่น" (ตรวจที่ฝั่งฐานข้อมูล ไม่ใช่แค่ซ่อนปุ่ม)

---

## ตัวเลข "ห้องว่าง" มาจากผังโดยตรง

หอที่วาดผังแล้ว ตัวเลขห้องว่างในหน้าค้นหาและในตารางราคา **นับจากช่องสีเทาในผัง**
ไม่ต้องมานั่งแก้ตัวเลขห้องว่างด้วยมืออีก — จัดการที่ผังที่เดียวจบ
(หอที่ยังไม่ได้วาดผัง ยังใช้ตัวเลขที่กรอกมือเหมือนเดิมทุกอย่าง)

# อัปเดต v22 — สถานะห้องเหลือ 2 แบบ / ดูรูปขนาดเต็ม

## ⚠️ รันไฟล์ `fix-v21.sql` ใน Supabase ก่อน แล้วค่อยอัปโหลดไฟล์เว็บ

ไฟล์นี้ย้ายข้อมูลสถานะห้องเดิม และแก้ trigger ตอนเจ้าของหอกดยืนยันรับจอง
**ถ้าไม่รัน** ห้องที่เจ้าของหายืนยันรับจองไปแล้วจะกลายเป็นสถานะที่เว็บไม่รู้จัก

---

## 1. สถานะห้องเหลือ 2 แบบ

| สี | สถานะ | หมายความว่า |
|---|---|---|
| 🟩 **เขียว** | ว่าง | จองได้ |
| 🟥 **แดง** | จองแล้ว | จองไม่ได้ (มีคนจอง / มีคนอยู่ / ปิดซ่อม) |

ของเดิมมี 4 สถานะ (ว่าง / มีคนจองแล้ว / มีผู้เช่าอยู่ / ปิดปรับปรุง) ซึ่งเยอะเกินจำเป็น
เพราะสำหรับนักศึกษามีแค่ 2 อย่างที่ต้องรู้: **จองได้ หรือ จองไม่ได้**

**ข้อมูลเก่าถูกย้ายให้อัตโนมัติ** — มีผู้เช่าอยู่ / ปิดปรับปรุง → กลายเป็น "จองแล้ว"
(เลือกให้เป็นจองแล้ว ไม่ใช่ว่าง เพราะถ้าเผลอทำให้ว่าง นักศึกษาจะกดจองห้องที่มีคนอยู่ได้)
เจ้าของหอเปิดห้องพวกนี้กลับเป็นว่างเองได้จากหน้าผัง

วงจรการจองยังทำงานเหมือนเดิม แค่สีไม่เปลี่ยนตอนยืนยัน:

```
นักศึกษากดจอง      -> แดง
เจ้าของหอกดยืนยัน   -> แดง (เหมือนเดิม)
ยกเลิก / ปฏิเสธ    -> เขียว
```

---

## 2. ปุ่ม + และ 🪜 มีตัวหนังสือกำกับแล้ว

เดิมมีแต่ไอคอน เดาไม่ออกว่ากดแล้วได้อะไร ตอนนี้เขียนว่า **"เพิ่มห้อง"** และ **"เพิ่มบันได"**

---

## 3. รูปหอ — กดดูขนาดเต็มได้

- กดที่**รูปปก**หรือ**รูปย่อ**ใบไหนก็ได้ → เปิดดูเต็มจอ **ตามสัดส่วนจริงของรูป** ไม่ครอบ ไม่ยืด
- มีปุ่ม ‹ › เลื่อนดูรูปถัดไป และใช้ปุ่มลูกศรซ้าย/ขวาบนคีย์บอร์ดได้
- กด Esc หรือกดพื้นที่ว่างรอบรูปเพื่อปิด
- **เอาปุ่ม "เพิ่มรูปจากเครื่อง" ที่ทับบนรูปปกออกแล้ว** — ใช้ช่อง **＋ เพิ่มรูป**
  ท้ายแถวรูปย่อแทน (ปุ่ม "ดูหน้าที่นักศึกษาเห็น" ยังอยู่ที่เดิม)

---

## 4. เอาตาราง "เลือกห้องพักของคุณ" ออก

หอที่วาดผังห้องไว้แล้ว จะไม่มีตารางประเภทห้องซ้ำอีก เพราะผังห้องบอกครบกว่า
(เลขห้อง ชั้น ราคาเฉพาะห้อง ของในห้อง และจองรายห้องได้)

หมายเหตุ: หอที่ **ยังไม่ได้วาดผัง** ตารางนี้ยังแสดงอยู่ ไม่งั้นนักศึกษาจะไม่เห็นราคาห้อง
และไม่มีที่กดจองเลย — พอเจ้าของหอวาดผังเสร็จ ตารางจะหายไปเอง

---

## 5. หน้าต่างรายละเอียดห้อง (ฝั่งนักศึกษา)

**สิ่งอำนวยความสะดวกในห้องตามที่เจ้าของหอติ๊กไว้** · ปุ่มจองห้อง (ถ้าห้องว่าง)
